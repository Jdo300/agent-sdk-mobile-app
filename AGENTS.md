# RG Link agent workflow

## Issue tracking is authoritative

For RG Link/Bloop development, GitHub Issues in this repository are the authoritative evolving list of bugs, feature enhancements, and deferred work.

- Before starting a bug fix or feature, search open issues and use the existing issue when one matches.
- If no matching issue exists, create one before substantial implementation work.
- Add meaningful findings, decisions, blockers, verification results, and progress updates to the issue as work proceeds.
- Reference the issue in commits/PRs when practical and close it only after the requested behavior is verified.
- Do not maintain a competing detailed bug/feature task list in Local Milo memory, spreadsheets, or ad-hoc files. Durable project memory may point to GitHub Issues and retain only stable project facts/policies that are useful outside the repo.
- Project-management tracking can still record high-level project status or milestones when operationally useful, but implementation details belong in GitHub Issues.

## Current product identity

- Product name: RG Link
- iOS bundle identifier: `com.resonancegroup.rglink`
- Native iOS experimentation/release work is isolated on `ios-native-build` until it is ready to merge.
